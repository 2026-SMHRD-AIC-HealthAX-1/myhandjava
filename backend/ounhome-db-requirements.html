Spring Boot · JPA(Hibernate) · MySQL 8 · WebSocket(STOMP)

1. 요구사항 정의서

  1. 사용자는 아이디, 비밀번호, 닉네임, 이메일, 성별 등 기본 정보를 등록(회원가입)할 수 있어야 하며, 카카오·구글 소셜 로그인 시에도 email이 같은 기존 계정으로 연결되어야 한다.

  2. 사용자의 거주 지역(시/구/동)을 저장하여 지역 기반 랭킹 조회 및 크루 매칭에 활용해야 한다.

  3. 사용자별 체형 보정(캘리브레이션) 결과를 저장하여, 이후 AI 자세 판정 시 개인 신체 비율 기준으로 각도를 보정할 수 있어야 한다.

  4. 운동 종목을 코드·종목명·타겟 부위·난이도로 구성된 카탈로그 형태로 관리해야 한다.

  5. 사용자가 AI 자세 판정으로 운동을 수행한 결과(반복 횟수, 정확도, PERFECT/GREAT/GOOD/MISS 등급 개수, 획득 포인트)를 회차별로 저장해야 한다.

  6. 하루 단위로 리셋되는 운동 진행 카운터(누적 반복수, 퍼펙트 개수, 완료 세트 수 등)를 관리하여 일일 미션 달성 여부를 판정할 수 있어야 한다.

  7. 사용자별로 매일 무작위 배정되는 미션(지표, 목표치, 보상, 달성/수령 여부)을 관리해야 한다.

  8. 사용자의 레벨·경험치·포인트·연속 출석일수를 누적 관리하여 게임화 요소(성장, 출석 보상)를 구현해야 한다.

  9. 상점에서 판매하는 아이템(가격, 카테고리, 착용 슬롯, 요구 레벨, 효과)을 관리하고, 사용자가 구매·장착한 아이템 보유 내역을 관리해야 한다.

  10. 사용자가 크루(소모임)를 생성·조회할 수 있어야 하며, 크루의 지역·컨셉·레벨·그룹 미션 정보를 관리해야 한다.

  11. 사용자의 크루 가입 신청과 크루장의 승인/거절, 크루원 목록 및 강퇴 처리를 관리해야 한다.

  12. 크루장이 작성하는 크루 공지사항(제목, 본문, 작성일시)을 관리해야 한다.

  13. 크루원 간 실시간 채팅 메시지를 발신자·전송시각별로 저장하여, 이후 채팅 이력을 다시 조회할 수 있어야 한다.

  14. 사용자가 남긴 문의(오류/기능요청/기타)와 관리자 답변, 처리 상태(접수/처리중/답변완료)를 관리해야 한다.

3. E-R Diagram

운동 종목(EXERCISE_DEFINITION)은 운동 기록의 exercise_type 문자열과 이름으로만 매칭되는 참조용 카탈로그이며, DB상 외래키 제약은 걸려 있지 않아 관계선을 그리지 않았다. 그 외 13개 객체는 모두 회원(USER) 또는 크루(CREW)를 기준으로 파생되는 1:N(또는 1:0..1) 관계다.

        varchar login_id

        bigint user_id FK

    EXERCISE_DEFINITION {

        varchar name

        varchar level

        varchar exercise_type

        int accuracy

        int points_awarded

        boolean claimed

        int level_req

        boolean equipped

        varchar status
        datetime created_at
